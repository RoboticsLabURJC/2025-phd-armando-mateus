Behavior Metrics: Right-Lane Percentage and Steering Zero-Crossings per Second — First PilotNet Run in Town02

October 20, 2026

📊 Part 1 — Overview: Two New Metrics Added to Behavior Metrics

📌 What Was Added

Two per-experiment metrics were added to Behavior Metrics: the percentage of frames in the right lane (right_lane_percentage) and the steering zero-crossings per second (steering_zero_crossings_per_second). Both are computed in the Python API backend from the CSV that the controller writes at every CARLA tick, and are stored in the experiment's summary JSON.

The process has two halves:

1. During recording (utils/controller_carla.py)

At each simulator tick, one CSV row is written. The patch adds five columns describing the lane the ego vehicle is in at that instant.

2. At recording stop (utils/metrics_carla.py)

get_metrics_python_api() reads the CSV and now calls _bm_extra_metrics(), which aggregates those columns together with the already existing steer column into the two metrics.

As extras, the summary JSON also keeps off_driving_lane_percentage, steering_zero_crossings (the total), and steering_zero_crossings_deadband (the deadband used).

New metrics travel from the CARLA tick to the JSON. Top: at each tick. Bottom: when recording stops. Blue: patch code.

📌 Why Python API and Not ROS

  • No ROS on this machine. The team uses Ubuntu 26.04.1 and ROS is not installed. The poetic-devel branch of Behavior Metrics and its carla-ros-bridge target ROS 1 Noetic, which corresponds to Ubuntu 20.04. Without ROS there is no bridge, no /carla/ego_vehicle/* topics, and no rosbags.
  • The ROS backend depends on rosbags. With ROS_VERSION set to 1 or 2, ControllerCarla.record_metrics() launches rosbag record / ros2 bag record on the bridge topics, and metrics_carla.get_metrics() processes the bag. None of that can run here.
  • The Python API backend already existed and is the one that runs. With ROS_VERSION=None, the controller subscribes to world.on_tick, writes the CSV with _sample_row(), and finally calls get_metrics_python_api() (line 597 of the controller). The new metrics are inserted exactly on that path.
  • driver_carla.py forces this mode anyway. It reads os.environ.get('ROS_VERSION ') with trailing spaces, so it always falls into Python API. controller_carla.py reads the variable correctly, which is why ROS_VERSION=None must be exported.
  • The map is at hand. The controller already has self.carla_map and self.ego_vehicle, so the lane is queried with carla_map.get_waypoint() at the same tick. On the ROS path it would have to be reconstructed from the bag odometry.

Lane at each tick: _bm_lane_info() (controller_carla.py)

get_waypoint(..., project_to_road=False) returns None if the car center is not over a driving lane. If it is, the frame counts as right lane when the heading difference with the lane is less than 90° (right-hand traffic). With BM_RIGHT_LANE_MODE=rightmost it also requires that there is no other Driving lane to its right.

# --- BM_EXTRA_METRICS: lane of the ego at each step ---
def _bm_lane_info(self, t):
    """[road_id, lane_id, heading_diff, on_driving_lane, in_right_lane] for transform t."""
    try:
        wp = self.carla_map.get_waypoint(
            t.location, project_to_road=False, lane_type=carla.LaneType.Driving
        )
        if wp is None:
            return ["", "", "", 0, 0] # outside a driving lane
        diff = (t.rotation.yaw - wp.transform.rotation.yaw + 180.0) % 360.0 - 180.0
        ok = abs(diff) < 90.0 # same direction as the lane (right-hand traffic)
        if ok and os.environ.get("BM_RIGHT_LANE_MODE", "direction") == "rightmost":
            right = wp.get_right_lane()
            ok = right is None or right.lane_type != carla.LaneType.Driving
        return [wp.road_id, wp.lane_id, round(diff, 2), 1, int(ok)]
    except Exception:
        return ["", "", "", 0, 0]

Metric computation: _bm_extra_metrics() (metrics_carla.py)

Right-lane percentage, with N CSV rows:
right_lane_percentage = (100 / N) · Σᵢ in_right_laneᵢ
Steering zero-crossings per second:

Each steer value (the one applied to the vehicle, get_control().steer) is converted into a sign sᵢ. Values inside the deadband d (0.02 by default, BM_STEER_DEADBAND) have no sign and are discarded. Changes between consecutive remaining signs are counted (K values) and divided by the simulated time T:

sᵢ = sign(steerᵢ) if |steerᵢ| ≥ d ; discarded otherwise
crossings/s = (1/T) · Σₖ₌₂ᴷ [sₖ ≠ sₖ₋₁]

Thus, a sequence +0.10 → 0.01 → −0.10 counts as a single crossing, and noise around 0 on straight sections does not add up.

# -- BM_EXTRA_METRICS --
def _bm_extra_metrics(df, experiment_metrics):
    """Right lane (% of frames) and steering zero-crossings per second."""
    try:
        deadband = float(os.environ.get("BM_STEER_DEADBAND", "0.02"))
    except ValueError:
        deadband = 0.02

    # Right lane: fraction of CSV rows with in_right_lane == 1
    if "in_right_lane" in df.columns and len(df) > 0:
        right = pd.to_numeric(df["in_right_lane"], errors="coerce").fillna(0).to_numpy()
        experiment_metrics["right_lane_percentage"] = float(100.0 * right.mean())
        if "on_driving_lane" in df.columns:
            on = pd.to_numeric(df["on_driving_lane"], errors="coerce").fillna(0).to_numpy()
            experiment_metrics["off_driving_lane_percentage"] = float(100.0 * (1.0 - on.mean()))
    else:
        experiment_metrics["right_lane_percentage"] = None # old CSV without the column

    # Zero-crossings with deadband and hysteresis
    steer = pd.to_numeric(df["steer"], errors="coerce").fillna(0.0).to_numpy()
    signs = np.where(np.abs(steer) >= deadband, np.sign(steer), 0.0)
    firm = signs[signs != 0]
    crossings = int(np.count_nonzero(firm[1:] != firm[:-1])) if len(firm) > 1 else 0
    duration = float(experiment_metrics.get("experiment_total_simulated_time", 0.0) or 0.0)
    experiment_metrics["steering_zero_crossings"] = crossings
    experiment_metrics["steering_zero_crossings_per_second"] = (
        crossings / duration if duration > 0 else 0.0
    )
    experiment_metrics["steering_zero_crossings_deadband"] = deadband
    print("[BM_EXTRA_METRICS] right lane: ... | zero crossings: ...") # console summary
    return experiment_metrics

The aplicar_metricas.py script

  • Backup: saves controller_carla.py.metricas.bak and metrics_carla.py.metricas.bak only the first time.
  • Idempotent: if a file already contains BM_EXTRA_METRICS, it does not touch it.
  • All or nothing: checks all anchors before writing; if one is missing, it does not modify any file.
  • Compilation: compiles each file after the patch and restores the original if it fails.
  • Revert: python3 aplicar_metricas.py --revertir restores the backups.
  • Path: uses ~/BehaviorMetrics/behavior_metrics by default, or the one indicated by BM_DIR.

📈 Part 4 — First Run: PilotNet in Town02

Run 20261020-101251 shows a model that steers smoothly but with a constant left bias, which ends up taking it off the road and crashing around second 20. It lasted 26.95 simulated seconds and produced 2372 rows (about 88 ticks per second); it traveled 66.6 m at an average of 9.1 km/h.

📌 Interpretation

Lane. When the car is on the roadway, it is in the correct lane 92% of the time (53.5 / 58.1). The main problem is not invading the oncoming lane but going off the road.

Careful with the 41.9%. It is a percentage of frames, not of distance, and the CSV keeps writing with the car stopped. The collision impulse was active in the last 564 rows (about 6.4 s), so the car was stopped after the crash. If it was outside the lane, that segment alone contributes about 24 points. The time off the road while moving is probably around 18%; the Step 6 breakdown confirms it.

Steering. In CARLA the yaw grows clockwise and a negative steer turns left. The negative mean steering and negative heading inside the lane indicate lateral drift to the left. Without the trajectory, it cannot be ruled out that part of it is a legitimate left curve of the route.

Zero crossings. 0.30/s means the model does not oscillate, but a low value is not good by itself: a biased model that always corrects to the same side also crosses little. It must be read together with the right-lane percentage. In addition, the brain smoothing (0.7 previous + 0.3 new) filters part of the network's oscillation: the metric measures the car, not the raw output.

🧪 What the First Run Shows

The two new metrics are correct and capture a real behavior: a smooth but biased controller that drifts left and leaves the road. The next step is to use them as an objective comparison tool across models and seeds, together with the existing cte_media and fuera_pct from the offline/online ranking.

⚠️ Part 5 — Limitations and Next Steps

The two new metrics are correct, but collisions and lane invasions in the Python API backend are still inflated by two bugs in the original code:

🐞 Known Bugs That Affect the Metrics

  • Sticky collisions. _last_collision_impulse never returns to 0, so after the first crash every row counts as a collision (564 in this run).
  • Phantom invasions. An empty _last_lane_invasion is saved as an empty field; pandas reads it as NaN, astype(str) turns it into "nan", and every row counts as an invasion (2372 of 2372).
  • Percentage by frames. The CSV keeps writing with the car stopped, so an early crash inflates off_driving_lane_percentage. Versions "while moving" and "up to the first crash" should also be computed.
  • Lane by car center. on_driving_lane looks only at the vehicle center: with half the car outside the lane it still counts as inside.
  • GUI. The Metrics window still does not show the new metrics; they are in the JSON and the console.
