PilotNet in Behavior Metrics: Brain v2 vs. Own Driver — Seed Independence with EMA

October 27, 2026

📊 Part 1 — Overview

📌 Two Questions Closed This Week

  • PilotNet in Behavior Metrics. Models that drove well in the training pipeline crashed quickly inside Behavior Metrics. A new brain (v2) replicates the own driver's semantics and was validated in Town02.
  • Seed independence with EMA. Whether an EMA of the weights can make single models independent of the training seed, as the 5-seed ensemble had achieved.

Short answer: brain v2 works (428 m before understeering into a guardrail), but EMA 0.9999 does not deliver seed independence (14 of 60 single models still fail).

🛠️ Part 2 — Diagnosis and Brain v2

The initial hypothesis (FPS and sync/async mode) was only partly right. Three differences carried the weight:

AspectOwn driverPrevious brain in BMWeight
Simulation modeSynchronous, fixed_delta_seconds = 0.05, one tick() per decisionAsynchronous; brain decides every 50 ms real timeHigh
Image seen by modelFrom the current tick, via a frame-indexed queueLast image delivered by callback, variable delayHigh

Start-up60 ticks braked so the car settlesDrives from the first instantMedium

🐞 Three Additional Findings

  • FPS do not matter. The driver enables sync mode and imposes 0.05 s per tick (20 Hz simulated).
  • Speed control was a bug in the previous brain, which copied the old agent. Without braking in curves, the car enters fast and opens the arc.
  • Behavior Metrics' sync mode does not work here. With AsyncMode: False it enables sync mode without fixing fixed_delta_seconds, and two processes call tick() at once: the pilot and the world generator.

Solution: brain v2

Sync mode was moved into the brain. The YAML keeps AsyncMode: True; the brain is the only one advancing the simulator. Per step:

  1. On first play, enables synchronous_mode with fixed_delta_seconds = 0.05 and creates its own 800×600 camera with a frame-indexed queue.
  2. Keeps the car braked for 60 ticks (3 s simulated) so it settles.
  3. At each decision calls tick(), takes the image from that same frame and predicts steering.
  4. Smooths steering and computes throttle/brake with the same PID as the own driver.
  5. Sends all three values in a single apply_control.

Files added: brain_carla_pilotnet_pth.py (v2, supports ensembles), pilotnet_town02_sync.yml (same parameters as own driver, ClearNoon at 0 % cloudiness), and carla_async.py (restores async mode if CARLA is left frozen after an abrupt close).

📌 Interpretation

  • Synchrony works. Every row advances exactly 0.05 s and one frame, same as the own driver.
  • Speed control works. Speed stays between 14.2 and 15.2 km/h around the 15 km/h target.
  • The car no longer crashes quickly. It covers 428 m and several curves before failing.
  • The crash is understeer in a curve. In the last second the car's heading separates 48° from the lane, but applied steering never exceeds 0.23; the model asks for little wheel and the 0.3 smoothing delays the response further.

🐞 Caveats When Reading the Metrics

  • Collisions are inflated. Behavior Metrics does not stop the run on crash, and the PID keeps accelerating against the guardrail; the 101 collision rows are a single crash.
  • lane_invasion may carry its value across events. The 45 % is an indication of the bias, not an exact measure; in_right_lane is more reliable.

Phase 1 — Cycle per change (repeat for 1, 2, 3)

  1. Issue with the six sections required by CONTRIBUTING.md: expected behavior, current behavior, reproduction steps, environment, possible cause, possible solution.
  2. Branch from the most recent version:
    git fetch upstream
    git checkout -b feature/NNN-external-carla upstream/noetic-devel
  3. Port the change without copying .bak or unrelated files.

  5. Commit and push, file by file:

    git commit -m "Allow using an external CARLA server without killing it"
    git push origin feature/NNN-external-carla
  6. Pull request against noetic-devel, with Fixes #NNN, how it was tested and in which environment (Ubuntu 26.04, Python 3.10, CARLA 0.9.15 in Docker, no ROS).
  7. Answer review in days or weeks, not months.

Phase 2 — Sync mode in the core (change 4)

This change touches central behavior, so agree on the approach with maintainers in the issue before coding.

  • Issue with the evidence: with AsyncMode: False fixed_delta_seconds is not fixed, pilot and world generator call tick() at once, and the brain receives the last image instead of the current tick's. Cite PR #719, which addressed asynchrony but not this.
  • Propose the design: a FixedDelta key in YAML; only the pilot calls tick(); the world generator stops calling it; the camera delivers the current frame's image.
  • Implement using the v2 brain logic as reference.
  • Validate with the trace: step of exactly 0.05 s, consecutive frames and two identical runs giving the same trajectory.
  • Once integrated, simplify the PilotNet brain to use Behavior Metrics' sync mode instead of its own.

🐞 Not Proposed to the Repository

  • The PilotNet brain as-is, because it depends on the project's pilotnet_model.py; at most a generic version could be offered as an example.
  • Local install adjustments: PyTorch versions for the RTX 5070, requirements-base.txt and pinned numpy.

⚠️ Limitations

  • No ROS on Ubuntu 26.04, so the changes cannot be tested in ROS mode; this must be stated in every PR.
  • Review and integration depend on maintainers; meanwhile, the local installation keeps working with the current patches.

🌱 Part 5 — Independence of the Training Seed with EMA

PropertyMeaningState
DeterminismSame seed and data give the same model, bit for bitSolved
Seed independenceDifferent seeds give models that drive the sameNot solved: the seed decides whether the car passes certain points of the route

The symptom is a lottery: with the same dataset, one model passes point A (~60 m) and another, trained with a different seed, crashes there. The 5-seed ensemble had already attenuated this. Question: could EMA achieve the same for a single model?

Hypothesis: EMA as a filter

EMA keeps an exponential moving average of the weights and validates/saves that average, not the raw weights. It is a first-order IIR low-pass filter with pole at z = β:

θ̄ₜ = β θ̄ₜ₋₁ + (1 − β) θₜ

The seed injects high-frequency noise; the filter attenuates it. With batch 32 and 52,700 images, one epoch is 1646 steps: β = 0.9999 has a ~6-epoch window. Expected limitation: the filter averages within one trajectory; if two seeds lead to different minima, it does not bring them together.

Experiment 1: β sweep

100 Comp0 datasets × β ∈ {0.99, 0.999, 0.9999} × 1 seed (42), cap 200 epochs; paired comparison dataset by dataset. It measured quality, not seed dependence.

Metric (v2, common pool)0.990.9990.99990.9999 vs. 0.999
MAE0.04290.04290.0424−1.2 %, better in 82/100
R²0.8720.8720.874+0.0025, better in 84/100
Slope0.8790.8770.878+0.0016, no practical effect

🐞 Defect Found and Fixed

The average started from the random weights of the freshly created model: with 0.9999 those weights still weighed 85 % after 1 epoch and 19 % after 10, lengthening early stopping and delaying the LR drops of the plateau scheduler. A bias correction was added (Adam-style, dividing by 1 − βᵗ); the average was verified to match Adam's formula and training remains reproducible bit for bit.

Experiment 2: 12 datasets × 5 seeds on the track

With β = 0.9999 and bias correction, 46 of 60 single models reached the gas station; the other 14 failed at point A (~60 m) or at a new point C (~230–250 m). 11 Comp0 datasets of 62,000 images and one of 309,000, seeds 42, 1, 2, 3, 4, cap 300 epochs, each model driven alone in Town02.

📌 Headline

14 of 60 single models do not reach the gas station; in 10 of 12 datasets at least one seed fails. Only two datasets arrived with all 5 seeds: Comp0-seed0 and the 309,000-image one.

Analysis

  • Reaching the gas station. A single model reaches B 75 % of the time. The expected distribution if each seed were a fair coin matches the observed one: there are no "bad" datasets (5-of-5: 2.5 expected vs. 1; 4-of-5: 4.36 vs. 3; 3-of-5: 3.04 vs. 4; 2-or-fewer: 1.2 vs. 0).
  • Centering. |cte| varies ±0.11 m between seeds of the same dataset and ±0.05 m between dataset means (ANOVA p = 0.56). The seed explains ~77 % of the variation and the dataset ~23 %.
  • The large dataset. Its 5 seeds reached B and are well centered (|cte| 0.596 m). Suggests more data reduces seed dependence, but it is a single case and 5 of 5 by chance has a 27 % probability.
  • By seed. s3 reached B in all 12 datasets and s4 in 6. With 12 datasets this may be coincidence; a seed is not good in itself.

🐞 Why EMA is not enough

  • It attenuates high frequency, not the trajectory. The seed fixes initialization and data order, which decide which minimum training heads to; the filter averages within that trajectory and does not bring two trajectories together.
  • Threshold decisions remain. Early stopping and the plateau scheduler cross their thresholds at different moments per seed, and from there the models diverge.
  • Minimal offline differences, binary effect on the track. Slope changed ±0.002 between β values; in closed loop, a small difference in a critical curve decides between continuing and crashing.
  • Points A and C are weak zones of the data. Any seed variation pushes the model one way or the other.

What follows

  • Review the ranking of the 12 ensembles (ranking_ensembles_run81_ema0.9999bc.csv): if datasets with 2 failing seeds still reach B as ensembles, the ensemble confirms itself as the solution.
  • Watch the failure videos at A and C to understand what the model sees there.
  • Add data from stretches A and C, and from the gas station (B).
  • Test whether more data reduces seed dependence with more than one large dataset.
  • Try a cosine scheduler, which does not depend on validation and removes one of the threshold decisions.

📌 WEEK 48 SUMMARY – OCTOBER 27, 2026

🎯 Objective: Validate the new Behavior Metrics brain (v2) against the training pipeline, and determine whether EMA can make model quality independent of the training seed.

🧪 Methodologies: Brain v2 replicating the own driver's semantics inside Behavior Metrics (sync mode, frame-indexed camera queue, settle ticks, PID in simulated time, single apply_control), with AsyncMode: True in YAML. Upstream integration planned as four independent issues/branches/PRs against noetic-devel. EMA β sweep over 100 datasets, then 12 datasets × 5 seeds with bias correction.

📈 Key Findings: Brain v2 reproduces the own driver's conditions: exact 0.05 s steps, consecutive frames, correct weather and model. The model covered 428 m in 104.3 s before understeering into a guardrail at 48° heading error, with applied steering never above 0.23. Speed control works (14.2–15.2 km/h around a 15 km/h target). FPS do not influence behavior; sync mode, speed control and start-up settling were the real differences. EMA 0.9999 with bias correction is a minor quality gain (MAE −1.2 %, R² +0.0025) but does not deliver seed independence: 14 of 60 single models fail, and in 10 of 12 datasets at least one seed fails. The seed explains ~77 % of centering variation, the dataset ~23 %.

✅ Achievements: Behavior Metrics now drives under the same conditions as the training pipeline; the remaining gap is model behavior, to be compared with the own driver. Upstream contribution plan defined with four scoped changes. EMA bias-correction defect found and fixed; training remains reproducible bit for bit.

❌ Limitations: Collisions in Behavior Metrics are inflated (run does not stop on crash); lane_invasion may carry across events. The 0.9.14 vs. 0.9.15 comparison is still pending. No ROS on Ubuntu 26.04, so upstream changes cannot be tested in ROS mode. The large-dataset evidence for reduced seed dependence is a single case (5 of 5 by chance has 27 % probability).
